# turma learnings (write-back)

How the craft gets sharper. When a specialist runs on a real project and a result comes in, the generalizable lesson is logged here, then promoted into the skill it belongs to.

## The one rule

Raw project data stays in the project. Only the distilled, generalized technique crosses back into turma. One client's numbers never land in another client's playbook. If you can't state the lesson without naming a client's private data, it isn't ready to promote.

## Entry format

```
### [date] / [skill touched] / [vertical tag]
- Tried:      [the specific move. hook pattern, format, cadence, offer framing]
- Against:    [the alternative it beat or lost to]
- Result:     [the number. "3:1 on saves," "opt-in 4% -> 9%," "0 lift"]
- Sample:     [how much data, what could confound it]
- Lesson:     [the portable version, tagged by vertical/context. NOT the raw content.]
- Confidence: [hunch / signal / strong]
- Change:     [what tactic to add or edit in which SKILL.md, once confidence is strong]
```

## Vertical tags

Tag every lesson so future installs can filter to what's relevant:

`[dtc-health]` `[b2b-saas]` `[creator/newsletter]` `[local-service]` `[fintech]` `[ecommerce]` `[general]` ...

## Promotion

A lesson at **strong** confidence gets written into the relevant skill's SKILL.md as an updated tactic, tagged by the vertical it's proven in. Until then it lives here as a candidate. Same discipline as the old rule-candidate flow: nothing edits a skill silently.
